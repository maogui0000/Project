# (D) 留言板：雙向互動與 LINE Bot 照護者連結 — 需求規格書

## 1. 功能概述

本功能旨在透過智慧陪伴系統與 LINE Bot 的整合，建立長者與照護者（家人）之間的雙向溝通橋樑。照護者可透過 LINE Bot 即時接收長者的生活動態，並傳送關懷留言；長者則透過陪伴系統以語音方式收聽留言並口述回覆，實現零門檻的跨世代溝通。

> 本版範圍：單一照護者對單一長者（1:1），未來再擴充多照護者綁定。

## 2. 互動流程設計

### 2.1 照護者端（LINE Bot）

#### 即時動態接收（已有功能，擴充整合）

| 項目 | 說明 |
|------|------|
| 觸發條件 | 長者與陪伴系統完成對話 Session 後自動推播（現有 `_send_line_session_summary` 機制） |
| 推播對象 | 已綁定的照護者 LINE 帳號（`LINE_TARGET_USER_ID`） |
| 推播方式 | LINE Bot Push API 主動推播 |

#### 動態推播範例

| 事件類型 | 推播內容範例 |
|---------|------------|
| 對話摘要 | 「阿公今天聊了以前在宜蘭的生活，聊了 15 分鐘，心情不錯！」 |
| 健康異常 | 「⚠️ 阿嬤剛才表示頭暈不舒服，系統已建議就醫。」 |
| 情緒偵測 | 「阿公今天情緒偏低落，建議找時間關心一下。」 |
| 用藥提醒 | 「阿嬤中午已服用降血壓藥。」 |

#### 發送關懷留言

| 項目 | 說明 |
|------|------|
| 操作方式 | 照護者在 LINE Bot 中直接傳送訊息（文字或語音） |
| 支援格式 | 文字訊息、語音訊息 |
| 字數限制 | 文字留言建議 100 字以內（避免長者聆聽疲累） |
| 語音限制 | 語音留言建議 60 秒以內 |

#### 照護者 LINE Bot 功能選單

| 功能按鈕 | 說明 |
|---------|------|
| 📩 傳送留言給長者 | 直接輸入文字或錄製語音留言 |
| 📊 查看今日動態 | 查看長者當日互動摘要 |

---

### 2.2 長者端（陪伴系統）

#### 主動播報留言

| 項目 | 說明 |
|------|------|
| 觸發條件 | 長者開始與系統互動時（喚醒詞「小黃小黃」觸發後），若有未讀留言則主動提醒 |
| 系統提醒 | 「阿公！家人剛才在 LINE 上留了訊息給你喔，要聽聽看嗎？」 |

#### 對話流程

| 步驟 | 角色 | 內容 |
|------|------|------|
| 1 | 系統 | 「阿公！家人剛才在 LINE 上留了訊息給你喔，要聽聽看嗎？」 |
| 2a | 長者（同意） | 「好」「聽聽看」「他說什麼？」 |
| 2b | 長者（稍後） | 「等一下」「晚點再聽」 |
| 3 | 系統（播報） | 播放留言內容（文字轉語音或直接播放語音檔） |
| 4 | 系統 | 「聽完了，要不要回覆家人呢？」 |
| 5a | 長者（回覆） | 口述回應內容 |
| 5b | 長者（不回覆） | 「不用」「沒什麼要說的」 |
| 6 | 系統（回覆後） | 「好的，我幫你傳給家人囉！」 |

#### 互動回復機制

| 項目 | 說明 |
|------|------|
| 回覆方式 | 長者直接口述，前端錄音 |
| 處理方式 | 語音轉文字（瀏覽器 Web Speech API）+ 文字內容回傳 |
| 回傳目標 | 照護者的 LINE Bot |
| 回傳格式 | 文字訊息（轉譯結果） |

## 3. 技術與系統實作需求

### 3.1 系統架構（基於現有架構擴充）

#### 現有元件複用

| 元件 | 說明 |
|------|------|
| `app.py` (FastAPI) | 新增留言相關 API 端點 |
| `services/line_bot.py` (Flask) | 擴充 Webhook 接收照護者留言 |
| `core/data_manager.py` | 擴充留言資料讀寫方法 |
| `web/index.html` | 前端對話邏輯中加入留言播報流程 |

#### 新增元件

| 元件 | 說明 |
|------|------|
| `data/<elder_id>/messages.json` | 留言佇列（JSON 檔案，與現有資料結構一致） |

### 3.2 資料模型

#### 留言資料結構（`messages.json`）

```json
{
  "elder_id": "elder_178546685908e66b",
  "messages": [
    {
      "message_id": "msg_20250801_001",
      "sender_type": "caregiver",
      "sender_name": "家人",
      "content_type": "text",
      "content_text": "爸，我今晚會買排骨湯回去看你喔！",
      "content_audio_url": null,
      "status": "unread",
      "created_at": "2025-08-01T14:30:00",
      "read_at": null,
      "reply_text": null,
      "replied_at": null
    }
  ]
}
```

#### 留言狀態

| 狀態 | 說明 | 觸發條件 |
|------|------|---------|
| `unread` | 未讀，待播報 | 照護者發送留言時 |
| `read` | 已讀，已播報 | 長者系統播報完畢時 |
| `replied` | 已回覆 | 長者口述回覆完成時 |

### 3.3 API 設計

#### 新增端點

| 方法 | 路徑 | 說明 |
|------|------|------|
| GET | `/api/messages/{elder_id}/unread` | 取得未讀留言列表 |
| POST | `/api/messages/{elder_id}/mark_read` | 標記留言為已讀 |
| POST | `/api/messages/{elder_id}/reply` | 長者回覆留言 |

#### LINE Bot Webhook 擴充

| 事件 | 處理方式 |
|------|---------|
| 照護者傳送文字訊息 | 存入 `messages.json`，狀態設為 `unread` |
| 照護者傳送語音訊息 | 下載音檔存入 `data/<elder_id>/audio/`，存入 messages.json |

### 3.4 前端整合

| 時機 | 行為 |
|------|------|
| 對話開始時（喚醒詞觸發後） | 呼叫 `/api/messages/{elder_id}/unread`，若有未讀則 TTS 提醒 |
| 長者同意聽留言 | TTS 播報留言內容，呼叫 mark_read |
| 長者口述回覆 | 前端錄音 → Web Speech API 轉文字 → POST `/api/messages/{elder_id}/reply` |
| 回覆完成 | 後端透過 LINE Push API 將回覆傳給照護者 |

### 3.5 LINE Bot 整合

| 需求項目 | 說明 |
|---------|------|
| API 版本 | LINE Messaging API v2（現有 `line-bot-sdk` 已支援） |
| 訊息類型 | 文字、語音 |
| Webhook | 擴充現有 `/callback` 路由，新增留言接收邏輯 |
| Push API | 推播長者回覆 + 已讀回報給照護者 |

## 4. 非功能性需求

| 項目 | 需求說明 |
|------|---------|
| 即時性 | 照護者留言須即時存入佇列；動態推播須於 Session 結束後 30 秒內送達 |
| 可靠性 | 留言以 JSON 檔案持久化，系統重啟後待播報留言仍可正常播報 |
| 安全性 | 訊息傳輸加密（HTTPS）；留言內容僅綁定之照護者與長者可存取 |
| 親和性 | 長者端全程語音互動，零操作門檻；照護者端 LINE 介面直覺易用 |

---

## 5. 驗收標準

1. 照護者能透過 LINE Bot 成功傳送文字留言給長者
2. 照護者能透過 LINE Bot 成功傳送語音留言給長者
3. 長者開始對話時（喚醒詞觸發後），系統能主動提醒有未讀留言並播報
4. 長者能口述回覆，系統正確完成語音轉文字並回傳照護者
5. 照護者能收到長者回覆的文字訊息
6. 留言狀態正確更新（unread → read → replied），照護者收到已讀回報
7. 留言以 JSON 持久化，系統重啟後待播報留言仍可正常播報
8. 長者端全程語音互動，無需手動操作任何按鈕
